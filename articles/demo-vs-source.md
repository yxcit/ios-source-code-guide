# Compare a demo with the delivered source project

A demo may have newer assets, different configuration, or a different release version than the delivered archive. Resolve that uncertainty before planning around its features.

## Build a comparison table

For each feature you care about, record the demo steps, the package's documented version, and whether the source build reproduces the behavior. Keep visual differences separate from missing functionality.

## Ask about hidden prerequisites

If a demo uses an account or backend, ask how those dependencies are configured in a fresh checkout. Identify which data is sample content and which must come from an external service.

## Test one real task

Choose a small end-to-end task instead of only navigating screens. For a record-keeping app, create a record, change it, find it again, and confirm its state after relaunch.

## Record unresolved differences

A mismatch does not identify its cause by itself. It might be a version difference, a missing configuration step, or a defect. Keep the observation concrete and ask the seller to explain how to reproduce the advertised behavior.
