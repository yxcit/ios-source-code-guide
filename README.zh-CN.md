# iOS 应用源码选购与首次构建指南

[English](README.md)

购买源码前，先确认交付内容、运行条件和许可范围。这份清单帮助独立开发者评估项目是否适合作为自己的开发起点，不代表任何商品已经通过下面的检查。

## 购买前确认

- **看实际功能。** 将商品说明、截图和演示逐项对照。商店中已上线的 App 与交付源码可能不是同一版本，请确认版本对应关系。
- **问清交付范围。** 是否包含 Xcode 工程、资源文件、安装说明、依赖版本、示例数据，以及需要的后端？不要把演示网站误当成随源码交付的服务。
- **确认开发环境。** 获取支持的 Xcode、系统和设备版本，了解签名、Bundle ID、权限描述和第三方服务需要怎样配置。
- **阅读许可。** 明确可以做哪些商业修改、允许几个项目使用、是否允许团队协作，以及源码再分发限制。第三方依赖和图片字体可能有各自的许可。
- **确认售后和交付方式。** 记录下载链接有效期、更新范围、支持渠道与退款条款。不要把付费源码的购买理解为保证 App Store 审核通过。

## 收到源码后第一次运行

1. 保存原始压缩包及交付说明，建立自己的 Git 仓库，暂不修改功能。
2. 按文档安装依赖，记录工具链与版本。只配置自己的签名和服务凭证，不使用卖家的生产密钥。
3. 使用虚构测试数据启动项目，检查关键路径：新建、编辑、保存、关闭重开、搜索、导出或删除。根据实际功能选择检查项。
4. 对需要网络的部分确认请求地址、费用、账号归属与离线行为。记录哪些能力依赖外部服务。
5. 保留可运行的基线提交，再逐步修改品牌、布局和业务逻辑。每次只改一个容易核对的部分。

## 报告问题时准备什么

写清工程版本、Xcode 和系统版本、设备或模拟器型号、最短复现步骤、预期和实际结果。日志只保留必要片段，移除令牌、密码和用户信息。保留原始工程用于对照，能帮助区分交付问题和后续修改问题。
